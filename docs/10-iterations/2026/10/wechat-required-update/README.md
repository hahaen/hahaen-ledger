# 微信小程序强制更新

日期：2026-10-04。

## requirement

用户要求全局发现不是最新代码包时，只允许重启更新后使用，不提供继续使用旧版本的选项。采用微信更新管理器，仅修改前端，不新增后端最低版本接口。

## design

应用启动同步注册全局更新事件。微信报告 hasUpdate 后立即进入专用更新页面，清空旧页面栈；全局导航拦截器和前台生命周期保持拦截。下载完成后单按钮提示“重启更新”，只在 onUpdateReady 后调用 applyUpdate。下载失败或超时保留更新页面，提示关闭小程序、检查网络再打开；迟到的下载成功事件仍可恢复到重启提示。重复启动/前台事件不重复注册、不叠加弹窗。

检查和下载由微信触发，不清空业务 Storage，不用 reLaunch 冒充代码更新。微信没有报告更新前不推断旧包；本功能不能证明任意离线客户端一定是最新版，也不能使尚未包含本功能的旧代码包主动执行新逻辑。开发/体验版不能作为正式版升级链路的验收证据。现有分享问题没有根因证据，本功能不宣称修复分享。

## database

不适用：无 Schema/Flyway/数据写入变化。

## api

无业务接口变化。只使用微信更新管理器和前端导航、提示 API。

## backend

不适用：Java、权限、金额、事务、幂等、Redis、MinIO 业务均无改动。

## frontend

已接入 App 启动（早于异步登录恢复）、应用/页面前台生命周期、五类 uni 导航拦截和独立更新页。微信差异集中在工具层及条件编译；H5 不注册微信更新检查，误入更新路由时回首页。更新页无返回/底栏入口，沿用品牌导航和绿色按钮，按钮至少48px、正文可滚动、错误提供恢复步骤；按钮白字/深绿背景对比度9.35:1。

## testing

11项定向测试执行真实工具状态机，仅替换微信、计时器等外部边界，覆盖无更新、有更新下载、准备完成、失败/60秒超时、晚到事件、弹窗失败、重启失败、重复事件、前台恢复及路由拦截。生产包检查加载实际编译后的 App 和更新工具，验证先注册管理器再恢复登录、全局钩子及 H5 排除；不将这些平台替身测试等同真机。微信工具正式构建目录使用内建“下次编译时模拟更新”完成成功/失败流程。真实正式版升级需要先发布含本功能的版本，再发布后续版本，不在本次授权中。
