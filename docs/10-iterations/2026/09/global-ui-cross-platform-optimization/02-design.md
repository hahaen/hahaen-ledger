# 设计

## 方案

1. 继续以 `prototype.scss` 和 `styles.scss` 为共享布局入口，不在页面中复制端特定样式。
2. 为认证页保留横向裁切但允许纵向滚动，避免小屏内容被截断。
3. 统一弹层 backdrop 的安全区内边距、动态视口最大高度和弹层内部滚动边界。
4. 为返回、协议链接、筛选/状态类按钮显式设置 `display:flex`、对齐、`line-height`、`min-width:0`，清除 uni-app/平台默认伪元素。
5. 对固定操作栏保持现有 z-index 和视觉规格，只补充内容底部留白与安全区，不改变业务入口。
6. 个人中心底部及修改密码确认按钮使用不依赖 CSS 变量的明确颜色，并清除微信原生按钮伪元素，保持 H5 既有视觉不变。
7. 小程序头像使用 `uni.chooseImage` 选择相册/相机图片，在工具层完成临时文件读取、真实图片类型识别、摘要计算和预签名 PUT；页面不调用微信资料获取接口。
8. 新增记账页将自定义 `screen-nav` 放在滚动内容外；仅在 `MP-WEIXIN` 条件编译下增加状态栏后的 44px 导航栏预留，并把 `.entry-type` 按钮的高度、最小高度、行高和内边距显式化。

## 风险控制

- 不改现有 API、script setup 业务代码和页面交互方法。
- 使用静态布局回归约束关键页面、弹层和固定区域。
- H5 和微信小程序分别构建；微信开发者工具若不可用，记录为 BLOCKED/NOT_RUN。
- 小程序导航栏高度采用微信自定义导航栏的标准 44px；真实胶囊位置、页面画面和点击行为仍需开发者工具或真机验证。
