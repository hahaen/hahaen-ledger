# `third-round`｜第三轮综合审计

## 迭代目的

本迭代用于对需求、架构、数据库、API、权限、金额、事务、幂等、缓存、文件、日志、测试、构建和文档进行一次跨层闭环审查。

## 应记录的重点

审计结论必须逐项绑定代码、Migration、命令输出、接口回归或截图证据，并严格区分 PASS、PARTIAL、FAIL、BLOCKED 和 NOT_RUN。重点关注“页面存在但业务不可用”“构建通过但依赖未联调”“前端传 userId”“逻辑删除未过滤”等假通过风险。
