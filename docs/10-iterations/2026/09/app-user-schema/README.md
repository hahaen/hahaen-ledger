# `app-user-schema`｜用户、身份与登录审计表

## 这次迭代解决什么问题

本次迭代为跨端账号体系建立数据基础：`app_user` 保存用户主数据和 H5 认证资料，`user_identity` 保存微信身份与用户的关联，`app_login_log` 保存登录成功/失败审计。这样 H5 账号和微信身份可以归属于同一个用户，而不需要把某一种登录渠道硬编码进用户主表。

## 范围与边界

- 包含 V1 基线中的三张用户相关表、唯一约束、审计字段和登录记录字段。
- 明确账号全表唯一、身份 `provider + open_id` 唯一、停用/逻辑删除后账号不可复用。
- 不包含 H5 登录接口、微信登录、跨端绑定页面、密码哈希服务和测试实现；这些能力在后续迭代中逐步接入。
- 不应把本目录的 SQL 设计误读成“所有认证流程都已完成”。

## 文件怎么读

`01` 说明需求和原型依据；`02` 说明用户与身份归属模型；`03` 对照 Flyway 和数据库约束；`04` 描述后续 API 规划；`05`、`06` 分别记录当时尚未实施的后端和前端范围；`07` 给出必须补充的测试；`08` 是实际命令；`09` 是当时的验证结论；`10` 说明尚未执行和已执行两种回滚边界。

## 状态说明

本目录的 SQL/设计结果与后续实现状态必须以各文件中的实际证据为准；接口、前端绑定和微信身份登录未在本迭代中完成的部分保持 `NOT_RUN`，后续完成不能改写为本次迭代已完成。
