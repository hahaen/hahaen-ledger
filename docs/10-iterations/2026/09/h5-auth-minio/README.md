# `h5-auth-minio`｜H5 认证与头像文件闭环

## 这次迭代解决什么问题

本次迭代把 H5 认证和头像文件链路接通：用户可通过账号、密码和图形验证码注册/登录，密码通过浏览器 Web Crypto 加密传输，服务端解密后只保存 BCrypt 哈希，并通过 Sa-Token 建立会话；头像使用 MinIO 短时效预签名 URL 上传、确认、预览和删除。

## 关键安全边界

- 验证码只在 Redis 保存且一次性消费，临时 Key 统一使用 `haji:` 前缀并设置 TTL。
- 登录失败不泄漏账号是否存在，并写入不含密码、Token 或微信 `open_id` 的审计日志。
- 文件接口每一步都按当前 Sa-Token 用户校验文件归属；前端不持有 MinIO 密钥，也不保存永久 URL。
- 当前只开放 `AVATAR`；账单附件要等账本和账单表建立后再开放。
