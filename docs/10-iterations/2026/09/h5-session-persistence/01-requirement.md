# 需求

## 来源

- 用户需求：刷新页面后继续当前页面，不应每次重新登录。
- 现有 H5 认证与 `h5-root-login` 启动规则。

## 目标

1. 有效会话刷新后保留当前 H5 页面。
2. 仅在没有会话或服务端明确判定会话失效时进入登录页。
3. 后端重启不使尚未过期的 Sa-Token 会话全部失效。
4. Redis 会话 Key 遵守项目 `haji:` 前缀规则。

## 验收条件

- 从首页、日历、资产、我的及带参数的详情页刷新后，页面路由不被改写。
- 有效 token 刷新后仍能调用需要认证的接口。
- 后端重启后，Redis 中的会话仍可被识别，除非已过期或主动退出。
- 未登录访问业务页仍跳转登录页；401/403 后清理前端会话并跳转登录页。
