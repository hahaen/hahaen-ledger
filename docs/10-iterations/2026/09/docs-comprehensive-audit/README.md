# 文档真实性全面审计

## 1. 审计目标

对 `docs/` 全部文档进行一次基于当前工作区的真实性审计，核对范围包括项目规范、当前代码、Flyway Migration、配置、接口、前端页面、测试证据和历史迭代档案。目标是修正当前规范中的错误或过时描述，补齐项目现状，并保留历史迭代在当时上下文中的真实性。

## 2. 审计边界

- 文档范围：`docs/` 下所有文件，包括根目录、`00-overview` 至 `10-iterations`、证据日志和历史迭代档案。
- 实现范围：`README.md`、`AGENTS.md`、`server/`、`app/`、`sql/`、原型目录及 Flyway 资源。
- 核对重点：目录与索引、领域命名、数据库字段与 Migration、API 与 DTO/VO、前端页面与 API 入口、配置与启动说明、验证状态和历史/当前文档边界。

## 3. 处理原则

1. 当前规范以代码、Migration、配置和可复现实测证据为准；需求或设计稿只在实现尚未落地时说明目标边界。
2. 历史迭代记录保留当时的需求、设计、命令和结论，不用当前实现反向改写历史。
3. 对无法由当前工作区确认的外部依赖状态，使用 `BLOCKED` 或 `NOT_RUN`，不把静态检查扩大为运行时 PASS。
4. 不删除有价值的历史记录；对重复内容通过索引、用途说明和状态标识降低歧义。

## 4. 交付文件

- `01-requirement.md`：审计范围、问题分类和验收标准。
- `02-design.md`：文档分层、权威性和整理方案。
- `03-database.md`：数据库与文档核对结果。
- `04-api.md`：接口、认证和前后端契约核对结果。
- `05-backend.md`：后端代码、配置和测试证据核对结果。
- `06-frontend.md`：前端页面、平台和设计实现核对结果。
- `07-testing.md`：本次审计执行的检查与结果。
- `08-commands.md`：真实执行的命令及结果摘要，不记录敏感信息。
- `09-verification.md`：最终结论、剩余风险和状态。
- `10-rollback.md`：本次文档变更的回退范围和方式。
