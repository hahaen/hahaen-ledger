# 审计设计

## 文档分层

1. `00-overview` 至 `08-design`：当前规范，描述现在应遵守的边界和实现事实。
2. `09-audit`：带证据的阶段结论，状态必须能回溯到命令、代码、运行探针或文件。
3. `10-iterations`：历史档案，保留当时的目标、选择、缺口和回滚，不反向改写。

## 整理决策

- 不删除历史 feature-key，即使后续实现已经改变历史文档中的“未实现”状态。
- 将当前接口清单集中到 `docs/03-api/README.md`，将数据库字段和约束集中到 `docs/02-database/`，避免在多个规范文件维护不同字段名。
- 在当前规范中明确“代码存在”“静态通过”“真实依赖已验证”是三种不同状态。
- 对微信认证、数据库实际迁移、头像对象链路和视觉截图等未闭环项显式记录风险，不用构建结果掩盖。
