# 前端

`utils/file.ts` 在 H5 上传前检查 10MB 上限，并以文件头识别 JPEG、PNG、WebP 或 GIF 的实际 MIME，避免把扩展名或浏览器声明 MIME 当作内容事实；随后使用 Web Crypto 计算 SHA-256 并申请上传授权。若后端返回 `READY`，不发起 MinIO PUT，直接请求既有预览 URL；否则照原流程 PUT、确认和预览。

因此扩展名为 `.png`、实际文件头为 JPEG 的常见图片可按 `image/jpeg` 上传；非上述类型或没有合法图片文件头的内容仍会在前端和后端被拒绝。

我的页和个人中心把资料字段改为 `avatarFileUrl`，图片显示始终使用短时 `viewUrl`。个人中心选择新头像后，文件会先上传并仅暂存 `fileId`，保留当前头像画面；点击“保存”时资料请求携带该 `avatarFileId`，成功后才切换预览图。上传中及保存中继续禁用头像入口，失败继续可重试。我的页头像点击统一进入个人中心，避免绕过保存流程直接替换头像。

后续 H5 回归发现全局选择器与 `display:none` 输入框在页面缓存/WebView 下可能不触发文件选择器；检查编译产物后确认 uni-app H5 会把模板 `input[type=file]` 改为文本输入。两个头像入口改为在用户点击手势内动态创建原生 `input[type=file]`、绑定既有回调并立即触发；个人中心按钮指定 `type="button"`。
