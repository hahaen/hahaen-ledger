# 09｜审计与验收证据

本目录保存阶段性审计、验证矩阵和验收结论，是项目当前“做到什么程度”的证据区。规范文档描述应该怎样做，审计文档描述实际上做了什么。

## 文档职责

- `verification-matrix.md`：按需求、数据库、API、后端、前端、权限、金额、事务、幂等、依赖和文档逐项映射证据。
- `third-round-audit.md`：第三轮整体审计结论、风险、剩余缺口和验收边界。
- `second-round-audit.md`：第二轮审计历史记录，保留当时的判断和证据上下文。

## 状态纪律

只能将“已执行且符合预期”的项目标记为 `PASS`。`PARTIAL` 必须列明剩余范围，`FAIL` 必须说明复现和影响，`BLOCKED` 必须写明外部依赖，`NOT_RUN` 不得被构建结果替代。

每轮重大修改完成后同步更新本目录、对应第三轮 iteration 和根目录索引；命令和日志不得泄漏任何 Secret。
