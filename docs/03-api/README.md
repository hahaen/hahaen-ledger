# 03｜API 规范

本目录说明前后端之间的协议边界。接口文档应让调用方知道请求、响应、错误、认证、归属、幂等和状态变化，而不是只列出 URL。

## 接口设计要求

- 当前用户和当前账本由服务端会话与业务上下文确定，绝不信任前端传入的 `userId` 作为权限依据。
- Controller 负责协议适配，业务判断放在 Service；错误统一使用项目约定的 `ApiResponse` 和异常体系。
- 所有写接口明确幂等键或防重复提交策略；金额和日期在前后端双重校验。
- 用户、账本、账户、账单、退款和文件的详情、删除、统计及关联查询都要排除逻辑删除数据。

## 变更同步

接口发生变化时，必须同步 DTO/VO、前端 `utils/api.ts`、页面 loading/失败重试逻辑、权限测试和对应迭代文档。未真实执行的接口联调只能记录为 `NOT_RUN` 或 `BLOCKED`。
